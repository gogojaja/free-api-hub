## P0 紧急整改（安全漏洞）

### D-S05：API Key 明文存储并提交至代码库

**缺陷等级**：严重  
**违反原则**：OWASP API Security Top 10 #2（Broken Authentication）、ISO/IEC 25010 §7 安全性

#### 问题描述

`config/chat.yaml` 和 `config/code.yaml` 中包含 6 个真实 API Key，均为明文：
- 智谱 AI Key：`ZHIPU_API_KEY_REPLACED`
- DeepSeek Key：`DEEPSEEK_API_KEY_REPLACED`
- OpenRouter Key：`OPENROUTER_API_KEY_REPLACED`
- 火山引擎 Key：`VOLCENGINE_API_KEY_REPLACED`

这些 Key 已提交至 Git 仓库，一旦仓库泄露将全部被窃取。

#### 整改方案

**步骤 1：创建 .env 文件（不提交至 Git）**

```bash
# 在项目根目录创建 .env 文件
cat > /Volumes/KINGSTON120G/free-api-hub/.env << 'EOF'
# 聊天实例
ZHIPU_API_KEY=ZHIPU_API_KEY_REPLACED
OPENROUTER_API_KEY=OPENROUTER_API_KEY_REPLACED

# 编程实例
DEEPSEEK_API_KEY=DEEPSEEK_API_KEY_REPLACED
VOLCENGINE_API_KEY=VOLCENGINE_API_KEY_REPLACED
EOF
```

**步骤 2：更新 .gitignore**

```gitignore
# 在 .gitignore 中添加
.env
config/*.yaml.local
```

**步骤 3：修改配置文件格式，支持环境变量引用**

在 `gateway.py` 的 `_load_config()` 方法中增加环境变量替换逻辑：

```python
import os

def _resolve_env(self, value):
    """将 ${ENV_VAR} 格式的值替换为环境变量"""
    if isinstance(value, str) and value.startswith("${") and value.endswith("}"):
        env_key = value[2:-1]
        return os.getenv(env_key, "")
    return value

def _load_config(self):
    # ... 原有加载逻辑 ...
    for p in self.config.get("providers", []):
        if "api_key" in p:
            p["api_key"] = self._resolve_env(p["api_key"])
        if "access_key_id" in p:
            p["access_key_id"] = self._resolve_env(p["access_key_id"])
        if "secret_access_key" in p:
            p["secret_access_key"] = self._resolve_env(p["secret_access_key"])
```

**步骤 4：修改 YAML 配置文件**

```yaml
# config/chat.yaml
providers:
  - name: zhipu
    api_key: ${ZHIPU_API_KEY}
    # ... 其他字段不变
```

**步骤 5：清除 Git 历史中的 Key**

```bash
# 使用 git filter-branch 或 BFG Repo-Cleaner 清除历史记录
# 注意：此操作会重写 Git 历史，需团队协调
bfg --replace-text passwords.txt
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```

**步骤 6：轮换所有 API Key**

在各自平台重新生成 API Key，旧 Key 作废。

#### 验收标准

- [ ] `config/*.yaml` 中无明文 API Key
- [ ] `.env` 文件已加入 `.gitignore`
- [ ] `git log -p` 中无历史 Key 记录
- [ ] 所有 API Key 已轮换
- [ ] 网关功能正常（启动后可正常调用各 Provider）

#### 回滚方案

若环境变量方案导致功能异常：
1. 恢复 `config/*.yaml` 备份（从 `backup/` 目录）
2. 暂时回退到明文配置，但立即将 `config/` 加入 `.gitignore`
3. 排查环境变量加载问题后重新切换

### D-S06：管理端点无认证保护

**缺陷等级**：严重  
**违反原则**：OWASP API Security Top 10 #1（Broken Object Level Authorization）

#### 问题描述

以下端点无任何认证机制：
- `GET /gateway/status`：返回全部 Provider 配置、用量数据、失败状态
- `POST /gateway/reset`：重置所有 Provider 失败状态

虽然绑定 `127.0.0.1`，但同机器上的任何进程均可调用。

#### 整改方案

**方案：API Token 认证中间件**

```python
# 在 server.py 中增加认证中间件

import os
from functools import wraps

ADMIN_TOKEN = os.getenv("ADMIN_TOKEN", "")  # 从环境变量读取

def require_auth(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        if not ADMIN_TOKEN:
            # 未配置 Token 时，仅允许本机访问但记录警告
            logger.warning("ADMIN_TOKEN 未配置，管理端点无认证保护")
            return f(*args, **kwargs)
        auth = request.headers.get("Authorization", "")
        if auth != f"Bearer {ADMIN_TOKEN}":
            return jsonify({"error": "Unauthorized"}), 401
        return f(*args, **kwargs)
    return decorated

@app.route("/gateway/status", methods=["GET"])
@require_auth
def gateway_status():
    # ... 原有逻辑 ...

@app.route("/gateway/reset", methods=["POST"])
@require_auth
def reset_gateway():
    # ... 原有逻辑 ...
```

**环境变量配置**：

```bash
# .env 文件中添加
ADMIN_TOKEN=$(python3 -c "import secrets; print(secrets.token_urlsafe(32))")
```

#### 验收标准

- [ ] 未携带正确 Token 访问 `/gateway/status` 返回 401
- [ ] 未携带正确 Token 访问 `/gateway/reset` 返回 401
- [ ] 携带正确 Token 可正常访问
- [ ] `/v1/chat/completions` 和 `/v1/models` 不受影响（保持无认证）

#### 回滚方案

移除 `@require_auth` 装饰器即可恢复原状。

### D-S07：Agent 任意代码执行（RCE 漏洞）

**缺陷等级**：严重  
**违反原则**：OWASP Top 10 #03 Injection、ISO/IEC 25010 §7 安全性

#### 问题描述

`src/agent.py` 中：
- `ToolExecutor._execute_code()`：直接 `subprocess.run([sys.executable, tmp])` 执行 LLM 生成的 Python 代码
- `ToolExecutor._run_command()`：使用 `shell=True` 执行任意命令
- 无沙箱隔离、无命令白名单、无路径限制

#### 整改方案

**推荐方案：移除 agent.py（优先）**

依据设计文档 v3.0 已记录"移除 Agent 层"的决策：

```bash
# 1. 备份
cp src/agent.py backup/agent.py.$(date +%Y%m%d%H%M%S)

# 2. 检查引用
grep -r "agent" src/ --include="*.py" | grep -v "agent.py"

# 3. 确认无引用后删除
rm src/agent.py

# 4. 更新设计文档，确认 Agent 层已移除
```

**替代方案：保留但增加沙箱（若需保留 Agent 功能）**

若业务需要保留 Agent 层：

```python
# 1. 使用 Docker 沙箱执行代码
class SandboxExecutor:

        # 写入临时文件

# 2. 移除 _run_command 的 shell=True
def _run_command(self, command: str) -> str:
    # 使用 shlex.split 替代 shell=True
```

**移除方案**：
- [ ] `src/agent.py` 已删除
- [ ] `grep -r "agent" src/ --include="*.py"` 无残留引用
- [ ] 网关功能不受影响
- [ ] 设计文档已更新

**保留方案**：
- [ ] 代码执行在 Docker 沙箱中运行
- [ ] `shell=True` 已移除
- [ ] 命令白名单生效
- [ ] 无网络访问权限
- [ ] 内存/CPU 限制生效

### D-S03：全部 Provider 失败时无降级策略

**缺陷等级**：严重  
**违反原则**：ISO/IEC 25010 §6.4 可恢复性、§6.3 容错性

#### 问题描述

所有 Provider 失败时仅返回 `{"error": "所有 API 均不可用"}` + 503 状态码，无任何降级机制。

#### 整改方案

**三级降级策略**：

```
Level 1: 熔断器模式
├── 单个 Provider 连续失败 3 次 → 熔断 60s
├── 半开状态：60s 后放一个请求试探
└── 闭环状态：成功 → 恢复，失败 → 重新熔断

Level 2: 缓存降级
├── 缓存最近 100 条成功响应（hash(messages) → response）
├── 全部 Provider 失败时，若缓存命中 → 返回缓存 + X-Cache-Hit 头
└── 缓存 TTL: 3600s

Level 3: 优雅降级响应
├── 缓存也未命中 → 返回结构化错误 + 建议操作
├── 响应体增加 retry_after 字段（建议重试等待时间）
└── 响应体增加 fallback_suggestion 字段
```

**实现要点**：

```python
# gateway.py 新增

class CircuitBreaker:
    def __init__(self, failure_threshold=3, recovery_timeout=60):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.failure_count = {}
        self.last_failure_time = {}
        self.state = {}  # closed / open / half_open

    def can_call(self, name):
        state = self.state.get(name, "closed")
        if state == "open":
            if time.time() - self.last_failure_time[name] > self.recovery_timeout:
                self.state[name] = "half_open"
                return True
            return False
        return True

    def record_success(self, name):
        self.failure_count[name] = 0
        self.state[name] = "closed"

    def record_failure(self, name):
        self.failure_count[name] = self.failure_count.get(name, 0) + 1
        self.last_failure_time[name] = time.time()
        if self.failure_count[name] >= self.failure_threshold:
            self.state[name] = "open"
```

#### 验收标准

- [ ] 单个 Provider 连续失败 3 次后自动熔断 60s
- [ ] 全部 Provider 失败时，若缓存命中则返回缓存响应
- [ ] 缓存未命中时返回结构化错误（含 retry_after）
- [ ] 熔断器恢复后自动尝试半开请求

#### 回滚方案

移除 CircuitBreaker 类和缓存逻辑，恢复原有直接返回错误的行为。
