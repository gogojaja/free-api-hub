### 稳定性风险分析

| 功能 | 稳定性风险 | 复杂度 | 对清单管理的价值 | 结论 |
|------|-----------|--------|-----------------|------|
| 基础 failover | ⚠️ 中等风险 | 高 | ❌ 无价值 | 禁止 |
| 熔断（Circuit Breaker） | ⚠️ 高风险 | 高 | ❌ 无价值 | 禁止 |
| 重试 + 指数退避 | ⚠️ 中等风险 | 中 | ❌ 无价值 | 禁止 |

**风险详解**：
- **failover**：增加路由逻辑复杂度，引入级联故障风险（A 失败可能是网络问题，B 也会失败）
- **熔断**：滑动窗口统计引入复杂状态管理，429/5xx 差异化冷却增加分支逻辑，熔断器本身可能误判（瞬时网络抖动 → 误熔断）
- **重试**：重试风暴风险（多个客户端同时重试），指数退避需要精确计时逻辑，429 Retry-After 解析可能出错

### 三项功能的现实意义分析

| 功能 | 场景 | 价值 | 复杂度 |
|------|------|------|--------|
| **failover** | 单提供商直连 | ❌ 无价值 | — |
| | 多提供商清单管理 | ❌ 无价值（清单不调用 API） | — |
| | 多提供商实际调用 | ⚠️ 有一定价值 | 高 |
| | 生产环境高可用 | ⚠️ 有价值 | 高 |
| **熔断** | 清单管理 | ❌ 无价值 | — |
| | 单提供商调用 | ❌ 无价值（没有备用） | — |
| | 多提供商调用 | ⚠️ 有一定价值 | 高 |
| | 高并发/生产环境 | ⚠️ 有价值 | 高 |
| **重试** | 清单管理 | ❌ 无价值 | — |
| | 偶发网络抖动 | ⚠️ 有价值 | 中 |
| | 限流处理 | ⚠️ 有价值 | 中 |
| | 生产环境稳定性 | ⚠️ 有价值 | 中 |

**综合结论**：
- **对 free-api-hub（清单管理）**：三项功能**完全无价值**，只有复杂度和稳定性风险
- **对 dev-model-router（智能路由）**：**有一定价值**，但需权衡（取决于是否直接调用 API）
- **对生产环境高可用网关**：**有价值**，但这是另一个项目定位

## 四、决策记录草案

- **标识**：ADR-2026-09-01-001（待架构角色正式编号）
- **决策**：明确 free-api-hub 定位：纯模型清单管理 + 轻量 OpenAI 兼容接口，禁止网关功能
- **选项**：
  - A. **明确分工（本方案）** → ✅ 消除矛盾，职责清晰，稳定性最高
  - B. 完全分离清单与网关 → ❌ 拆分成本高
  - C. 维持现状（矛盾共存） → ❌ 维护困难，稳定性风险
- **理由**：EV-920~924（三重矛盾 + 功能重叠 + 稳定性风险）
- **已验证**：交接文档/AGENTS.md/dev-platform-catalog（T1 本库实测）
- **不确定**：无
- **未关闭风险**：无
- **反信号**：无
