# AI 客户端模型路由配置手册

## 概述

将各 AI 客户端（opencode、VSCode 扩展）的请求指向 Free API Hub 网关（localhost:5080），由网关自动 failover 多个免费 API 提供商。

## 前提

Free API Hub 网关已在运行：
```bash
curl http://127.0.0.1:5080/health
# 返回: {"gateway_ready":true,"status":"ok"}
```

---

## 一、opencode 配置

### 配置位置（优先级高→低）

1. 命令行 `--config` 参数指定文件
2. 项目根目录 `opencode.json`
3. 项目根目录 `opencode.jsonc`
4. `~/.config/opencode/opencode.jsonc`

### 项目级配置（推荐）

在项目根目录创建 `opencode.json`:

```json
{
  "provider": "openai",
  "apiBase": "http://127.0.0.1:5080/v1",
  "model": "free-api-hub",
  "apiKey": "sk-placeholder"
}
```

### 全局配置

编辑 `~/.config/opencode/opencode.jsonc`:

```jsonc
{
  "provider": "openai",
  "apiBase": "http://127.0.0.1:5080/v1",
  "model": "free-api-hub",
  "apiKey": "sk-placeholder"
}
```

### 参数说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `provider` | `"openai"` | 使用 OpenAI 兼容协议 |
| `apiBase` | `"http://127.0.0.1:5080/v1"` | 指向 Free API Hub 网关 |
| `model` | `"free-api-hub"` | **会被网关忽略**，网关使用提供商自身配置的模型 |
| `apiKey` | `"sk-placeholder"` | **会被网关忽略**，网关使用 providers.yaml 中的 API Key |

### 验证

```bash
# 1. 确认网关在运行
curl http://127.0.0.1:5080/health

# 2. 检查可用提供商
curl http://127.0.0.1:5080/gateway/status | python3 -m json.tool

# 3. 在 opencode 中发送消息测试
opencode "Hello"
```

## 二、VSCode 扩展配置

### Continue 扩展

安装后编辑项目根目录 `.continuerc.json` 或全局配置 `~/.continue/config.json`:

```json
{
  "models": [
    {
      "title": "Free API Hub",
      "provider": "openai",
      "model": "free-api-hub",
      "apiBase": "http://127.0.0.1:5080/v1",
      "apiKey": "sk-placeholder",
      "completionOptions": {
        "temperature": 0.7,
        "maxTokens": 2048
      }
    }
  ],
  "tabAutocompleteModel": {
    "title": "Free API Hub (Tab)",
    "provider": "openai",
    "model": "free-api-hub",
    "apiBase": "http://127.0.0.1:5080/v1",
    "apiKey": "sk-placeholder"
  }
}
```

在 Continue 输入框发送消息验证输出。

### Cline 扩展

在 Cline 设置（侧边栏 Cline 图标 → 齿轮）中添加 API 提供商:
1. API Provider: **OpenAI Compatible**
2. Base URL: `http://127.0.0.1:5080/v1`
3. API Key: `sk-placeholder`（任意非空字符串）
4. Model: `free-api-hub`（任意非空字符串）

在 Cline 聊天窗口发送消息验证。

### Roo Code 扩展

在 Roo Code 设置中添加 API 提供商:
1. API Provider: **OpenAI Compatible**
2. Base URL: `http://127.0.0.1:5080/v1`
3. API Key: `sk-placeholder`
4. Model ID: `free-api-hub`

### GitHub Copilot

GitHub Copilot 不支持自定义 API 端点，无法指向 Free API Hub。如需自定义端点推荐使用 Continue 或 Cline。

## 三、通用验证与调试

### curl 测试

```bash
# 1. 检查连接
curl http://127.0.0.1:5080/v1/models

# 2. 测试对话
curl -X POST http://127.0.0.1:5080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"test","messages":[{"role":"user","content":"hello"}]}'
```

### 排查顺序（opencode 报错时）

```bash
# 1. 网关是否运行
curl http://127.0.0.1:5080/health

# 2. 提供商是否可用
curl http://127.0.0.1:5080/gateway/status

# 3. 直接测试对话接口
curl -X POST http://127.0.0.1:5080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"test","messages":[{"role":"user","content":"hi"}]}'

# 4. 查看网关日志
tail -30 /Volumes/KINGSTON120G/free-api-hub/data/gateway.log

# 5. 重置所有提供商的失败标记
curl -X POST http://127.0.0.1:5080/gateway/reset
```

### 常见问题

| 问题 | 解答 |
|------|------|
| 报 "401 Authentication Fails" | `apiKey` 不可为空，填入任意字符串如 `"sk-placeholder"`，网关实际使用 providers.yaml 中的 Key |
| 报 "model not found" | opencode 可能校验 model 值，填入任意非空字符串即可，网关会忽略它 |
| 所有提供商返回 503 | 所有 API 配额耗尽。更新 providers.yaml 中的 api_key，或通过 `/gateway/reset` 重试 |
| 某提供商一直失败 | 网关自动标记失败 60s。可通过 `/gateway/reset` 手动重置，或调整优先级让其他提供商优先 |

---

## 四、注意事项

1. **model 参数**：所有客户端传入的 model 值都会被 Free API Hub 忽略，每个提供商使用自身配置的模型
2. **API Key**：客户端要求 apiKey 不可为空。填入任意非空字符串即可
3. **流式支持**：Free API Hub 支持 SSE 流式，所有客户端的流式功能均可正常使用
4. **超时设置**：建议将客户端超时设置为 60s 以上，以留出 failover 时间
5. **端口冲突**：确保 5080 端口未被其他程序占用
