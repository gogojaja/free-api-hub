# Free API Hub 运维手册

> 配套《交接文档.md》使用。项目路径：`/Volumes/KINGSTON120G/free-api-hub`

## 1. 服务架构

- **chat 实例**：`http://127.0.0.1:5080`（OpenAI 兼容 `/v1/*`），配置 `config/chat.yaml`
- **code 实例**：`http://127.0.0.1:5081`（OpenAI 兼容 `/v1/*`），配置 `config/code.yaml`
- 双实例独立端口/配置/日志/用量文件；端口 5001/5002/5003 禁止操作

## 2. 常用命令

| 操作 | 命令 |
|------|------|
| 启动 chat | `nohup venv/bin/python src/server.py --config config/chat.yaml > data/chat_server.log 2>&1 &` |
| 启动 code | `nohup venv/bin/python src/server.py --config config/code.yaml > data/code_server.log 2>&1 &` |
| 停止 chat | `pkill -f "server.py --config config/chat.yaml"` |
| 查看日志 | `tail -f data/chat_server.log` |
| 健康检查 | `curl http://127.0.0.1:5080/health` / `/health/live` / `/health/ready` |
| 指标查看 | `curl http://127.0.0.1:5080/metrics`（Prometheus 文本，公开只读） |
| 网关状态 | `curl -H "Authorization: Bearer $ADMIN_TOKEN" http://127.0.0.1:5080/gateway/status` |
| 重置熔断 | `curl -X POST -H "Authorization: Bearer $ADMIN_TOKEN" http://127.0.0.1:5080/gateway/reset` |
| 单元测试 | `venv/bin/python tests/run_all_tests.py`（需 5080 在运行） |

## 3. launchd 守护（当前阻塞 ⚠️）

**状态**：launchd 守护因 macOS TCC 权限阻塞未启用，当前以手动进程运行。

**根因**：项目位于外部卷 `/Volumes/KINGSTON120G`，launchd 启动的进程访问外部卷需解释器二进制获 **完全磁盘访问**（TCC 按二进制授权，Apple 已移除命令行授权方式）。

**解决步骤**（一次性）：
1. 系统设置 → 隐私与安全性 → 完全磁盘访问 → 添加
   `/Library/Developer/CommandLineTools/Library/Frameworks/Python3.framework/Versions/3.9/Resources/Python.app`（或 `/usr/bin/python3`）
2. 安装守护：`bash scripts/install_daemon.sh install`
3. 核验：`launchctl list | grep freeapi` 双实例加载，双端口 `/health` 返回 ok
4. 自愈验证：`launchctl stop com.user.freeapihub.chat` → 数秒后 `launchctl list` 重新出现 PID → `/health` 恢复

**回滚**：`bash scripts/install_daemon.sh uninstall`

## 4. 运维要点

- **配置热加载**：修改 `config/*.yaml` 后 5s 内自动生效（无需重启）；改前自动快照至 `backup/config_v<N>_*.yaml`（保留 10 份）
- **熔断恢复**：provider 失败率 >25% 自动熔断，冷却后渐进恢复；可用 `/gateway/reset` 手动重置
- **用量持久化**：`data/*_usage.json`；升级前备份 `data/` 目录
- **配置备份**：`venv/bin/python scripts/backup_config.py`
- **日志**：`data/chat_server.log`（chat）、`data/code_server.log`（code）
- **禁止**：全库新建 `.xlsx`；操作主环境端口 5001/5002/5003

## 5. 故障恢复

1. 服务异常默认**从最新备份恢复**（`backup/` + git），仅收到明确排查指令才检修
2. 服务未启动：先 `ps aux | grep server.py`，无进程则按 §2 启动
3. 端口被占：`lsof -i :5080` 定位后清理冲突进程
4. API Key 需更新：编辑 `.env`（不提交 git），重启对应实例生效
